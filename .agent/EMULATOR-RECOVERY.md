# 模拟器恢复边界

本说明对应 2026-10-22 的模拟器卡死保护修复。

## 执行流程

- 后台 CrashGuard 只进行独立 ADB 探测和实例状态确认，持续失败至少 3 次且至少 60 秒才进入复核。
- 画面静止只记录诊断。任务本身的业务超时、点击保护仍保留。
- 检测线程提交恢复请求，使旧 Device 会话失效；不在任务执行中关闭或启动模拟器。
- 任务异常分类之前检查恢复请求。因此底层将会话异常改写成离线、页面错误或普通异常时，仍消费原请求一次。
- 任务退出后，协调器持有线程锁及跨进程实例锁，动作前持久化一次额度，释放旧设备资源，再执行一轮实例停启。
- 每轮最多一次停启；失败也计数。默认 6 小时 3 次，恢复尝试间隔 600 秒，失败、冷却或预算耗尽均停止当前配置。
- 实例记录位于 Windows 的 LOCALAPPDATA/AzurPilot/emulator-recovery，其他系统位于用户状态目录。不应通过删除记录规避故障。
- 独立探针在同一 300 秒期限内检查 ADB、系统启动完成、目标包名和有效的 1280×720 截图。系统就绪后，由新 Device 和 Restart 任务完成控制初始化与游戏登录。

## 两个必须保持的不变量

1. 原生 IPC 超时不能等同于原生调用已终止。MuMu 的 NativeCall 不向线程注入异步异常；
   单次调用预算为一分钟（`NATIVE_CALL_TIMEOUT`），预算耗尽才永久封禁该 IPC 实例，
   即使迟到完成也不能再次输入或重连，也不能释放仍在使用的句柄。
   **封禁的是句柄，不是脚本进程**：超时抛 `NativeIpcTimeout`（继承
   `EmulatorNotRunningError`），由调度器按"模拟器离线"路径重启整台实例后继续挂机。
   设备挂死是设备的问题，把还能管理实例的自动化进程一起结束是本末倒置。
2. 整轮恢复锁由实际执行者持有至结束。外层超时只发出取消并停止配置，不能替其它线程释放锁；旧执行者在下一动作前再次检查取消。

## 隔离与兼容范围

- 禁止恢复路径调用共享 adb kill-server 或按进程名批量关闭模拟器。
- Windows 适配覆盖 MuMu12、MuMuX、雷电、蓝叠5、夜神和 MEmu 的实例级入口。身份或状态不能核实即拒绝动作，不扩大到共享服务。
- macOS、SSH 和其它未适配类型当前拒绝自动实例恢复，仍需人工处理。不能回退为猜测进程或执行共享服务停止。
- 新旧设备不共享点击计数器和卡死计时器。所有已封禁会话的截图、输入和迟到结果均被拒绝。
- 演练模式不消耗次数、不启停模拟器；只输出诊断。

## 验证范围

单元测试使用伪造 ADB 响应、临时文件、真实线程及独立 Python 子进程验证互斥、取消、预算和迟到结果；不连接或操作实际模拟器。

未实测各厂商所有版本的控制台、长时间宿主机故障及多开实际恢复。原生驱动永久阻塞时选择停止配置请求人工介入，不承诺无条件自动恢复。
